## 1. 背景与问题

早期[线索聚合与草稿生成](2026-10-14-线索与草稿生成.md)以人工选择消息、建立线索、生成只读草稿为目标。L1 线索实体、L2 线索界面已实施，草稿生成与界面仍待做。

产品访谈确认，系统最终用于生成可以发布的文章或博客。首批面向普通科技读者，文章应有趣、帮助了解行业事件，生成后通读核对并少量修改即可发布。阶段 4 需要包含自动事件选题、补充资料、提纲确认及系统内编辑保存，重新定义范围与完成标准。

## 2. 候选方案与决定

早期方案交付人工选消息后的只读草稿，人工仍需自行选题、补资料和编辑。访谈后的方案由系统发现事件选题、准备资料并生成提纲和全文，由用户选择选题、确认提纲、核对编辑后输出。用户选择后者作为本阶段目标；增加的实现与质量评审成本纳入新计划。

| 决策点 | 用户已确认的决定 |
| --- | --- |
| 读者 | 普通科技读者；觉得有意思，并了解行业发生的事情 |
| 首批内容 | 同一事件的多篇报道整合，去重并补齐信息；单篇有趣或重要报道也可推荐 |
| 事件边界 | 先围绕同一事件聚合；发布新闻、评测和反馈可共同支持同一事件 |
| 推荐依据 | 有趣、重要，展示推荐理由 |
| 触发与范围 | 用户点击「发现选题」；默认最近 7 天、全部订阅，有有限时间范围，可按分类或来源筛选 |
| 资料 | 读取原文，联网补充相关报道、官方一手资料和必要背景 |
| 风格与长度 | 科技博客为主，表达自然有趣，适度分析行业影响；长度按事件复杂度决定 |
| 写作流程 | 用户选题，系统准备资料并出提纲，用户调整确认后生成全文 |
| 可信度 | 关键事实可追溯，优先官方资料；事实、分析、推测区分；冲突与关键缺口提示；正文必要链接与文末来源列表 |
| 人工工作量 | 通读核对、少量措辞修改即可发布；大段重写、补关键事实不算达到目标 |
| 编辑与输出 | 系统内修改、保存版本，再复制或导出到个人博客和公众号编辑器 |
| 本阶段边界 | 文字与引用；配图、杂谈专栏、其他写作入口、定时推荐、自动发布留到后续 |

## 3. 与早期方案的关系

本记录替代早期记录中的产品口径；保留其作为已有 L1/L2 实现的历史依据。旧方案的任务表、版本锁定、合法引用校验和调用审计原则仍可复用。

| 早期规则 | 新口径与兼容影响 |
| --- | --- |
| 线索全部由人工选消息建立，不做自动事件发现 | 本阶段新增系统发现事件、用户选题；人工线索保留为辅助能力 |
| 至少 2 条消息才可建线索 | 允许单篇选题走完整流程；当前服务门槛需调整并补测试 |
| 最多 20 条、一篇草稿一次调用 | 当前代码限制作为现状保留；新流程的资料与调用预算实测后决定，不据此限制产品目标 |
| 输入仅限已有消息版本及加工结果 | 增加原文和外部补充资料，引用需覆盖实际使用的外部证据 |
| 直接生成只读草稿 | 先确认提纲、再生成全文；新增系统内编辑、人工保存版本与输出 |
| 合法来源 ID 即完成引用校验 | 身份校验继续保留；成稿还必须人工验证关键事实是否被来源支持 |

当前代码仍按早期 L1/L2 行为运行。这次修改只完成目标、验收和计划同步，不能将其视为新功能实施。新目标对应的规则和数据调整在后续完整变更中完成。

## 4. 对实现与验收的约束

- 选题扫描有明确起止时间，默认最近 7 天；补充背景可早于窗口，但保留原始时间。分类、来源与时间筛选必须真实影响输入。
- 关键词可用于候选召回，不能成为唯一入选路径；单篇和无关键词短快讯都要有覆盖样本。P1 仍需完成并记录 M11 人工复核结论，作为召回质量基线；新产品目标还需新增事件样本验收。
- RSS 固定消息版本；外部资料保存来源信息、获取时间与实际使用的证据。历史文章不能随源内容更新改写依据，资料不可用必须可见。
- 提纲确认与人工文章保存有独立状态和版本。重生成另存，保存失败保留编辑内容；已完成的阶段产物可恢复。
- 长任务遵守任务表 + worker；模型仅经 LLMProvider，复用提示词库、调度和审计；外部检索与网页读取经端口和适配器装配。结构化输出校验、分层、迁移、类型与 Web 界面规范继续适用。
- 内容人工验收至少 3 篇固定真实样本，覆盖多源事件、单篇有趣内容、背景补充与行业影响分析；各篇都达到少量修改即可发布。边界、冲突、失败与恢复另用固定 fixture 验证。
- 来源合法、自动测试通过、导出文件存在，分别只能证明对应结构或流程；成稿支持关系与博客/公众号输出效果要实际核对。
