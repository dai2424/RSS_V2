# 配置安全与运行产物

本文件约束配置、密钥、路径、日志和临时产物的边界。具体配置库、密钥服务和部署平台由项目自行决定。

## 1. 配置

- [必须] 生产代码不得硬编码绝对路径、密钥、凭据、环境地址或租户标识。
- [必须] 配置通过一个明确的读取和校验边界注入；业务模块不自行读取环境变量或配置文件。
- [约定] 记录配置来源和优先级，例如默认值、配置文件、环境变量和启动参数。
- [评审] 必填配置缺失、格式错误和互相冲突时，启动应尽早失败并给出可诊断信息。
- [可选] 不同环境使用不同配置集；敏感值只存放在仓库外或受控的密钥系统中。

## 2. 密钥与敏感数据

- [必须] 密钥不进入代码、版本库、普通日志、审计表、错误堆栈或接口响应。
- [必须] 展示和诊断只使用掩码、哈希或不可逆摘要；完整值仅在实际调用边界可见。
- [约定] 测试使用专用假值；禁止把真实生产凭据复制到测试 fixture、截图或示例配置。
- [评审] 新增敏感字段时说明保存位置、访问者、轮换方式、撤销方式和保留周期。

## 3. 路径与运行目录

- [必须] 数据库、日志、备份、缓存、上传文件、构建结果和导出物写入 `<运行目录>` 或项目明确配置的路径。
- [必须] 代码目录只保存源代码、迁移、测试、文档和必要的静态资源。
- [CI] 仓库检查阻止数据库文件、日志、缓存、密钥和运行输出入库。
- [约定] 每类产物有可识别的子目录和清理策略；临时文件使用系统临时目录或任务专用目录。
- [评审] 运行目录不存在、无权限或磁盘不足时，程序返回明确错误而不是静默降级。

## 4. 日志与隐私

- [必须] 日志不记录密钥、会话凭据、完整个人数据或无需保存的原始输入。
- [约定] 日志使用结构化字段，包含事件名、时间、级别、关联标识和错误分类。
- [评审] 记录数据保留期、访问权限、脱敏规则和删除方式。
- [可选] 对外错误与内部日志分开；对外只返回可理解的原因和恢复建议。

## 5. 仓库卫生

- [必须] 提交前检查工作树，确认没有未追踪的敏感文件或运行产物。
- [约定] 提供 `.gitignore`、示例配置和本地检查命令；示例配置中的值必须是假值。
- [评审] 测试、构建和开发脚本不得修改业务数据或固定 demo 目录。
