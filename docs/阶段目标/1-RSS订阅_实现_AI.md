# RSS 订阅实现说明（AI）

当前范围依据用户确认的实现计划：来源与分类、RSS 采集与版本、翻译与 Key 池、独立 worker、React 工作台。人工需求原稿保持不变。

## 已实现的行为

- SQLite 编号 SQL 迁移、校验和检查、WAL、短事务与在线备份；采集运行和任务原子创建。
- 来源新增、编辑、启停、分类筛选与健康历史；内置分类和自定义分类并存。
- 原文纯文本保存，按来源外部 ID、规范化 URL、内容哈希去重；内容变化追加版本，包括 A → B → A。
- 翻译绑定入队时的消息版本、首选模型名和 prompt 版本；成功结果复用。标题、摘要、正文全部经 Pydantic schema 校验。
- Provider 下多 Key 引用，优先级与冷却调度，按 Key 再按 Provider 切换；每次模型尝试记录 `llm_calls`。
- Worker 租约 token、续租、过期恢复、三次有限自动重试、失败后手动重排；自动重试期间采集运行保持 running。译文写入与租约校验处于同一事务，过期 worker 不能覆盖新结果；翻译重试等待时间不短于 Key 冷却时间。
- 统一 OpenAPI 类型与稳定 API 错误码；本机 Host、Origin 和客户端地址检查。
- 单一 React 工作台覆盖来源、消息、任务和模型配置；路由懒加载，筛选与分页保存在 URL，表单失败保留输入，离开未保存表单时可继续编辑。

## 实现边界与评审

当前检索使用 `LIKE`；不接入定时任务、v1 数据迁移、局域网认证、图谱、发布或外部分布式队列。

前端构建写入 `runtime/frontend/`，可配置；API 和 worker 的配置、密钥环境必须一致。API 不执行持久化后台任务，续租线程仅在 worker 进程内运行。

日常运行统一使用根目录 `start.cmd`。启动器自动准备锁定依赖、按源文件指纹更新前端、执行迁移，启动 API 与独立 worker 并打开页面。两个子进程继承同一配置与密钥环境；Ctrl+C 或任一子进程退出时停止本次启动的两个进程。日志写入运行目录；端口占用时明确报错，不结束已有进程。

保留三个超过默认 60 行评审阈值的函数：`bootstrap.build_container`、`api.app.create_app` 是完整装配清单，内嵌处理函数各自较短；`HTTPXFeedClient.fetch` 是单次下载与 RSS 边界映射。业务翻译已拆为输入检查、单次尝试、审计与结果保存；路由、仓储按领域拆分。后续复杂度增长时重新评审这些例外。

前端手写组件文件均不超过 200 行。12 个展示函数超过 60 行，主要是完整表单和表格的 JSX；本次评审保留其完整展示结构。来源数据用例、字段与历史面板，Provider 配置、Key 设置与离开保护已分别拆分；新增业务规则应进入数据 hooks 或用例，不能继续堆入展示函数。OpenAPI 生成文件不计入规模阈值。

数据库操作时间和消息发布时间使用 UTC 秒整数。Feed 的原始更新时间文本属于来源元数据。采集统计按来源记录最近一次尝试；任务最终状态决定整个运行何时完成。

进程崩溃后的任务会重做幂等检查，成功译文能避免重复调用。若进程在模型返回与译文持久化之间被强制终止，恢复后仍可能再次调用外部模型；跨外部 API 和 SQLite 不承诺 exactly-once。

## 验证记录

- 后端：迁移回滚与校验、升级保留译文、来源编辑与停用、重复采集、版本变化、来源失败隔离、Key/Provider 切换、有限重试、租约 fencing、重启恢复、备份恢复、本机访问限制和分层导入约束。
- 一键启动：实际执行 `start.cmd --no-browser` 验证页面、API 与 worker 可用；再次启动复用已安装依赖及构建页面，重复启动提示端口占用，Ctrl+C 后两个子进程均退出。新增真实子进程测试，验证 API 退出会回收 worker；数据均使用临时目录。
- 浏览器：1440 / 768 / 390 像素下通过来源新增、编辑、采集、原文/译文切换、停用保留历史和键盘导航；另验证来源与 Provider 保存失败保留输入、配置编辑关闭确认、未保存离开提示及窄屏 Key 引用配置。
- 视觉：检查代表性来源、译文与配置页截图；12 组主题文字和控件配色通过对比度计算，文字至少 4.5:1，输入轮廓及焦点至少 3:1。
- 手动真实兼容 API 联调：`deepseek-v4.1-flash` 完成三字段结构化翻译，单次调用约 5.2 秒、511 tokens。凭据仅临时从外部配置读入内存，联调数据库位于系统临时目录并已清理。

检查结果：Ruff lint / format、Pyright、前端 typecheck / format / build 全部通过；后端 37 项、前端单元 9 项、浏览器 6 项测试通过。OpenAPI 与后端一致，文档相对链接有效，已检查真实联调凭据未进入任何待提交文件。

自动化验收使用 fake provider / 固定 fixture，不依赖真实密钥。浏览器数据库及代表性截图保存在被忽略的 `runtime/e2e/` 与 `frontend/test-results/`。当前依赖有 TestClient 弃用提示及 Zod 构建注释提示，未导致检查失败；升级依赖时复核。
