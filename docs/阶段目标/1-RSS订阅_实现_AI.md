# RSS 订阅实现说明（AI）

当前范围依据用户确认的实现计划：来源与分类、RSS 采集与版本、翻译与 Key 池、独立 worker、React 工作台。人工需求原稿保持不变。

## 已实现的行为

- SQLite 编号 SQL 迁移、校验和检查、WAL、短事务与在线备份；采集运行和任务原子创建。
- 来源新增、编辑、启停、分类筛选与健康历史；内置分类和自定义分类并存。
- 原文纯文本保存，按来源外部 ID、规范化 URL、内容哈希去重；内容变化追加版本，包括 A → B → A。
- 翻译绑定入队时的消息版本、首选模型名和 prompt 版本；成功结果复用。标题、摘要、正文全部经 Pydantic schema 校验。
- Provider 下多 Key 引用，优先级与冷却调度，按 Key 再按 Provider 切换；每次模型尝试记录 `llm_calls`。
- Worker 租约 token、续租、过期恢复、三次有限自动重试、失败后手动重排；自动重试期间采集运行保持 running。
- 统一 OpenAPI 类型与稳定 API 错误码；本机 Host、Origin 和客户端地址检查。

## 实现边界与评审

当前检索使用 `LIKE`；不接入定时任务、v1 数据迁移、局域网认证、图谱、发布或外部分布式队列。

前端构建写入 `runtime/frontend/`，可配置；API 和 worker 的配置、密钥环境必须一致。API 不执行持久化后台任务，续租线程仅在 worker 进程内运行。

保留三个超过默认 60 行评审阈值的函数：`bootstrap.build_container`、`api.app.create_app` 是完整装配清单，内嵌处理函数各自较短；`HTTPXFeedClient.fetch` 是单次下载与 RSS 边界映射。业务翻译已拆为输入检查、单次尝试、审计与结果保存；路由、仓储按领域拆分。后续复杂度增长时重新评审这些例外。

数据库操作时间和消息发布时间使用 UTC 秒整数。Feed 的原始更新时间文本属于来源元数据。采集统计按来源记录最近一次尝试；任务最终状态决定整个运行何时完成。

进程崩溃后的任务会重做幂等检查，成功译文能避免重复调用。若进程在模型返回与译文持久化之间被强制终止，恢复后仍可能再次调用外部模型；跨外部 API 和 SQLite 不承诺 exactly-once。

## 验证记录

- 后端：迁移回滚与校验、升级保留译文、来源编辑与停用、重复采集、版本变化、来源失败隔离、Key/Provider 切换、有限重试、租约 fencing、重启恢复、备份恢复、本机访问限制和分层导入约束。
- 浏览器：1440 / 768 / 390 像素下通过来源新增、采集、原文/译文切换、停用保留历史和键盘导航；另验证保存失败保留输入与未保存离开提示。
- 手动真实兼容 API 联调：`deepseek-v4.1-flash` 完成三字段结构化翻译，单次调用约 5.2 秒、511 tokens。凭据仅临时从外部配置读入内存，联调数据库位于系统临时目录并已清理。

最终检查结果随本阶段完成提交更新；自动化验收使用 fake provider / 固定 fixture，不依赖真实密钥。
