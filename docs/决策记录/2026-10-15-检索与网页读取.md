# 决策记录：联网检索与网页读取

> 状态：已接受（阶段 4 实施契约；P3a 按此实现，真实联网待实例与验证）
> 日期：2026-10-15
> 参与者：lyx（选定 SearXNG 兼容端点）、实现 Agent
> 影响范围：资料准备阶段的外部检索与正文读取（P3a/P3b）；阶段 4 之前项目没有联网检索能力。
> 依据：[阶段目标 4](../阶段目标/4-文章聚合_AI.md)（资料用途与来源支持规则）、[Agent 执行清单](../阶段目标/4-文章聚合_Agent执行清单.md) P1b 第 5 项与 P3a。

## 1. 背景与问题

产品要求"选题后读取原文、联网补充相关报道、官方一手资料与必要背景"。项目现有外部能力只有 RSS 抓取（`HTTPXFeedClient`）与模型调用（`LLMProvider`），没有任何搜索服务配置。需要选定运行时真正可用的检索方案，并明确端口、适配器、配置、失败分类与限制，使 P3a 的实现与真实依赖分离：代码可先按 fixture 验证，接上实例后再做真实联网验证。

## 2. 候选方案与决定

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| SearXNG 兼容端点（自建或可用实例，JSON 输出） | 无需厂商 Key；查询参数与结果结构稳定；可指向自建实例，数据不经过第三方 | 需要实例且必须开启 JSON 格式；公共实例常限流、可能关闭 JSON | **采用**（用户已确认） |
| Tavily / Brave 等商业 API | 开箱可用、结果质量稳定 | 需要账号与 Key、按次计费、条款约束 | 保留为后续可加适配器，不在本阶段引入 |
| 模型自带联网/浏览器工具 | 无新依赖 | 不是应用运行时能力，不可复现、不可审计 | 不采用（红线：模型记忆与搜索摘要不能冒充已读资料） |

## 3. 决定内容

### 3.1 端口

```text
SearchClient.search(query, *, limit, time_range=None) -> list[SearchHit]
    SearchHit{ title, url, snippet, published_at|None, engine }
ArticleReader.read(url) -> ReadResult
    ReadResult{ status, final_url, title, publisher, published_at|None,
                text, content_hash, byte_size, truncated, error_code, error_message }
```

- 端口定义在 `ports/web.py`（只依赖领域类型与标准库）；适配器放 `adapters/web/`，在 `bootstrap.py` 统一装配并注入 `MaterialService`。
- 端口只返回"命中/读取结果"，去重、状态映射与预算控制在服务层完成；适配器不写数据库。

### 3.2 SearXNG 适配器（`adapters/web/searxng.py`）

- 请求：`GET {search_base_url}/search`，参数 `q`、`format=json`、`language=all`、`safesearch=0`、`pageno=1`，可选 `time_range`（`day|month|year`，仅当需要时效收敛时使用）；`Accept: application/json`；超时 `search_timeout_seconds`（默认 20）。
- 结果解析：`results[]` 取 `url/title/content/engine/publishedDate`，条数上限 `search_result_limit`（默认 8）；忽略 `infoboxes/answers/suggestions`；`unresponsive_engines` 非空时记录到日志（不失败）。
- URL 规范化：去 fragment、host 小写、去掉跟踪参数（`utm_*`、`fbclid`、`gclid`、`ref`），用于去重键。
- 失败分类（映射到 `ExternalServiceError`，供任务重试分类；错误码写进资料行与任务错误信息）：

| 情况 | 错误码 | 处理 |
| --- | --- | --- |
| 未配置 `search_base_url` | `search_unconfigured` | 项目资料任务直接失败并提示配置缺失，不用假数据代替 |
| 连接失败/超时 | `search_network_error` / `search_timeout` | 可重试（冷却） |
| HTTP 401/403（含实例未开启 json 格式） | `search_format_disabled` | 不重试，提示检查实例配置 |
| HTTP 429 | `search_rate_limited` | 可重试（冷却） |
| HTTP 5xx | `search_server_error` | 可重试 |
| JSON 解析/结构不符 | `search_invalid_output` | 不重试，记录片段（脱敏） |
| 完全无结果 | 成功 + 空列表 | 记录为"无补充资料"，不当作失败 |

- 官方文档：<https://docs.searxng.org/dev/search_api.html>（`format=json` 需要在实例 `settings.yml` 的 `search.formats` 中开启，否则返回 403；公共实例常默认关闭）。**部署要求**：用户在 P3a 之前提供一个可用的 SearXNG 地址；本轮（P1a–P2b）不实现该适配器。

### 3.3 网页读取适配器（`adapters/web/reader.py`）

- 请求：`httpx` GET，`follow_redirects=True` 且最多 5 跳，超时 `article_read_timeout_seconds`（默认 20），`User-Agent` 标识项目；流式读取并累计字节，超过 `article_max_bytes`（默认 2 MB）停止读取、标记 `truncated=true` 并保留已读前缀。
- 协议与地址校验：只允许 `http`/`https`；解析后的 IP 属于回环、私网、链路本地或保留段时拒绝（`ssrf_blocked`）——检索结果来自外部，不能让它把应用当内网代理。
- 正文提取（`bs4`，不新增重依赖）：
  1. 优先 `<article>`，其次 `<main>`，再取正文密度最高的容器（段落文本长度加权）；
  2. 去除 `script/style/nav/footer/aside/form/iframe/noscript/svg` 与常见分享/推荐区（按 `class/id` 关键字：`share|related|comment|advert|promo|subscribe`）；
  3. 段落化输出纯文本（块级元素之间空行），保留有序/无序列表的项目符号；
  4. 元信息：`title` 取 `og:title` → `<h1>` → `<title>`；`publisher` 取 `og:site_name` → 域名；`published_at` 取 `article:published_time` → `og:published_time` → JSON-LD `datePublished`（解析失败留空，不猜测）。
- 状态映射：提取到 ≥400 字符 → `read`；正文不足但页面描述/摘要存在 → `summary_only`（保存摘要文本，正文留空）；HTTP 404/410 或明确下架 → `unavailable`；超时/网络/超限/解析失败 → `failed` 并记错误码。
- 内容指纹：规范化文本（去多余空白、统一标点）的 SHA-256，用于跨 URL 去重与"来源更新"判定。
- 日志：只记录 URL、状态、字节数与错误码，**不写正文**；错误片段按现有 `redact` 脱敏。

### 3.4 服务层规则（P3a/P3b）

- 输入资料：写作项目的窗口内成员消息版本（RSS 原文，能读则读；读不到的保留消息版本与摘要并标 `summary_only/unavailable`）。
- 补充检索：对每个项目发起 `materials_max_queries`（默认 3）次查询——事件关键词（中文）、事件关键词（英文/原名）、`site:` 限定官方来源（厂商/机构域名，来自事件主体）；查询文本由模型从候选标题/概要生成，写入任务结果以便复核。
- 命中只是候选：只有 `read` 成功的资料才能成为证据与引用，`summary_only` 只能作为线索提示（不能进正文引用）。
- 去重：同一规范化 URL 或同一 `content_hash` 只保留最先读取的一条，重复计数记入项目资料摘要。
- 历史背景允许早于发现窗口，但必须保留原始 `published_at`，正文不得把旧事写成新发生。
- 预算耗尽或部分失败：保留已获资料，资料行标记状态与错误码，项目转为"资料部分可用"，界面显示缺口；不静默丢资料、不用摘要冒充正文。

## 4. 影响

- 新增端口与适配器：`ports/web.py`、`adapters/web/searxng.py`、`adapters/web/reader.py`；`bootstrap.py` 增加装配；`settings.py` 与 `config/settings.example.toml` 增加 `search_base_url`、`search_timeout_seconds`、`search_result_limit`、`article_read_timeout_seconds`、`article_max_bytes`、`materials_max_queries`、`materials_max_reads`。
- 新增外部依赖失败面：搜索实例不可用、实例未开 JSON、被限流、目标站点反爬。所有情况都必须表现为"资料缺口 + 可诊断错误"，不得降级为"没有资料"。
- 测试：`respx` fixture 覆盖搜索命中/空结果/403/429/5xx/非法 JSON、读取重定向/超时/超限/摘要页/404/SSRF；真实联网验证在用户提供实例后单独进行并记录证据。
