# 决策记录：关键词页面与图表

> 状态：已实施（2026-10-09，关键词管理模块第 3 步）
> 背景：统计接口有了，但数字要落到页面上才有用。这一层要回答三个问题：图表用什么画、无障碍与降级怎么保证、合并这样的破坏性操作怎么做才敢用。

## 结论

1. **页面位置**：新增 `/settings/keywords`（侧栏"关键词"），与模型配置、提示词、任务分配同属设置组；导航只加已经可用的功能，本页只读统计 + 合并 + 回填/重建两个已有动作。
2. **图表库选 recharts**：技术选型第 9 节此前写明"图表等后端契约稳定后再增加"，现在契约（概览端点）稳定了，按该条件引入。选它的理由是 React 原生、无第三方运行时依赖、类型齐全；代价是懒加载分片从 0 涨到约 400 kB（gzip 117 kB），但路由级代码分割保证它不进主包——消息、来源等页面不受影响。回退路径：若后续出现兼容问题，图表是纯展示层，页面结构与数据契约不变，可以换回 CSS 条形。
3. **图表不靠颜色表意，且都有数据表兜底**：每个图表都是 `figure`，外框 `role="img"` + `aria-label` 描述数据，标题下有一句文字摘要（趋势峰值、长尾占比、来源冠军），并带一个默认折叠的同数据表格。色觉差异读者与屏幕阅读器拿到的信息和看图的人一致，也满足界面规范"状态同时有文字"。序列色只区分"词位数"与"新增词"，取自设计变量（`--chart-series-1/2`），不新增一套主题色。
4. **合并是破坏性操作，交互动线写死**：勾选两个以上词条后才出现"合并选中的词"；弹层里先选保留哪个写法，再展示影响面（并入几个词条、合并后有几种写法、多少个词位、影响多少条消息），确认后才执行；提示语明确写"不要合并上下位关系（尊界 与 尊界V800）"。执行后 Toast 指向合并记录，撤销入口就在同一页。
5. **空态区分"没有词"和"词被折叠了"**：词表默认折叠只出现一次的写法（当前占九成），如果这时显示"还没有关键词"会让人以为数据没进来。空态因此分三种：没有匹配结果（有筛选）、只有出现一次的写法（提示改成包含孤词）、真的还没有关键词（提示去回填）。
6. **重建索引与回填放在页面右上角**：两者此前只有接口，现在有了入口。回填先 `dry_run` 预览条数再执行，并在弹层里写明"每条会调用一次模型"；重建索引不调用模型，只把已有加工结果重新写入索引。
7. **e2e 覆盖到颜色解析**：图表断言不只"元素存在"，还包括线条的计算样式不是 `none`、不是默认黑——这能真实拦住"CSS 变量在 SVG 属性里没解析"这类只会被眼睛发现的问题。用例开头会撤销历史上遗留的合并，保证可重复执行。

## 影响范围

- 前端：新增 `features/keywords/`（`KeywordsPage`、`KeywordCharts`、`KeywordVocabulary`、`KeywordMerges`、`KeywordMaintenance`、`useKeywordsData` 与图表纯函数测试）；`App.tsx` 路由与 `AppShell.tsx` 导航各加一项；`styles.css` 加关键词页与图表样式；新增依赖 `recharts`。
- 前端测试：`e2e/support.ts` 抽出 worker 辅助（原来只在 workflow.spec.ts 里），新增 `e2e/keywords.spec.ts`（1280/1920 两个宽度）。
