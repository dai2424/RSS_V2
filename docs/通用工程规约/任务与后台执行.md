# 任务与后台执行

本文件适用于需要异步、批处理、定时或可恢复执行的项目。没有后台任务时，可以标记整份文件为 `[可选]`。

## 1. 单一执行路径

- [必须] 同一类后台工作只保留一套权威执行机制：入口创建任务，持久化任务记录，独立 worker 领取并执行。
- [必须] 入口线程、请求线程池和任务表不得同时承担同一类工作的状态管理。
- [约定] 调度器只负责按计划创建任务，不直接执行任务业务逻辑。
- [评审] 项目如果采用消息系统、任务队列或平台调度器，需在技术附录中说明其唯一职责和替代关系。

## 2. 任务记录

每个任务至少需要以下信息：

- 类型和版本；
- 输入标识或输入快照；
- 幂等键；
- 状态、创建时间、开始时间和完成时间；
- 尝试次数、最大尝试次数和下一次执行时间；
- 租约持有者与租约截止时间；
- 错误分类、可读原因和关联日志标识。

推荐状态：

```text
queued → running → succeeded
             ├──→ retry_wait → running
             └──→ failed
```

状态名称和转换条件由项目补充，不允许多个模块各自定义同一状态的含义。

## 3. 幂等、重试与租约

- [必须] 任务处理函数在重复领取、进程重启和网络重试下保持幂等。
- [必须] 领取任务和更新租约具有并发安全保证；同一任务不能被两个 worker 同时当作有效执行。
- [必须] worker 崩溃后，过期租约能被回收；回收过程不能清除仍在运行的有效任务。
- [约定] 重试按错误类别决定：可恢复错误重试，不可恢复错误直接失败；退避、上限和抖动写入配置。
- [评审] 重试不应重复发送不可逆副作用；必要时使用幂等键、去重记录或补偿操作。
- [CI] 至少测试重复领取、超时回收、重启恢复、最大重试次数和幂等结果。

## 4. 可观测性和运维

- [必须] 每次领取、开始、续租、重试、成功和失败都有结构化记录。
- [约定] 任务列表能区分等待、执行中、成功、可重试失败和最终失败。
- [可选] 提供暂停、取消、手动重试和死信处理；这些操作必须保留审计信息。
- [评审] 任务输入版本、代码版本和配置版本足以解释一次历史结果。
