# 数据与迁移

本文件约束持久化数据的所有权、结构演进、导入和恢复。项目使用何种存储由技术附录决定。

## 1. 数据所有权

- [必须] 每个表、集合、文件或外部记录都有明确的拥有模块和写入边界。
- [必须] 领域对象、传输对象和存储模型分开；应用层不依赖数据库行对象或游标对象。
- [约定] 时间统一使用 UTC 存储，展示时再按产品时区转换；时间字段注明单位。
- [约定] 枚举字段在数据字典中列出取值、含义、默认值和兼容策略。
- [评审] 新建字段或实体前检查现有模型，确认没有可复用的事实来源。

## 2. 迁移规则

- [必须] 每次结构变化使用独立、递增、可追踪的迁移文件。
- [必须] 已执行的迁移文件内容不可修改；修正必须新增迁移。
- [必须] 迁移执行器记录版本、校验和、执行时间和结果。
- [必须] 结构迁移由独立执行器完成，业务代码不得隐藏建表、改表或索引变更。
- [约定] 迁移在事务中执行；无法原子执行时记录明确的中间状态和恢复步骤。
- [CI] 至少在全新数据集和一份代表性旧数据集上执行迁移测试。

## 3. 数据回填与导入

- [必须] 结构迁移和业务数据导入分开；导入不能伪装成 schema 变化。
- [必须] 导入命令支持预览、幂等、限量或分批执行，并记录输入版本。
- [约定] 回填失败可以重试，不产生重复记录或覆盖人工修改。
- [评审] 导入前说明字段映射、缺失值、冲突处理、时间语义和回滚办法。
- [可选] 大规模回填应有进度、暂停、恢复和审计信息。

## 4. 删除、兼容与回滚

- [必须] 删除或改变字段前确认所有读写方、报表、任务和导出工具已迁移。
- [约定] 破坏性变化采用“先兼容、再迁移、后清理”的分阶段策略。
- [必须] 数据修复优先使用可审计的新迁移或修复命令，不直接手工改生产数据。
- [评审] 每项迁移都写明失败后的处理方式：事务回滚、前向修复、备份恢复或人工介入。
- [可选] 生产数据有可验证的备份、恢复演练和恢复时间目标。

## 5. 数据访问

- [必须] 业务查询和写入通过端口或仓储接口完成，SQL、查询 DSL 或驱动 API 只出现在适配器。
- [CI] 静态检查阻止应用层出现存储连接、游标、原始查询或结构变更语句。
- [约定] 事务边界由用例定义；不要把长时间外部请求放在数据事务中。
- [评审] 并发、唯一性、锁等待、超时和重试策略有测试或记录。
