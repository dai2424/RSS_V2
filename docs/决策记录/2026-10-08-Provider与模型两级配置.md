# 决策记录：Provider 与模型两级配置

> 状态：已实施（2026-10-08）
> 背景：原设计把"兼容服务"和"模型"合并成单字段 Provider，一个服务想换模型或用两个模型只能重复建 Provider，与通用 OpenAI 兼容网关（如 ZCode 自定义供应商）的用法不一致。

## 结论

1. **Provider 表示兼容服务连接**：Base URL、超时、会话头、非敏感请求头与一组 Key 引用；不含模型。
2. **新增模型实体**：`llm_provider_models(provider_id, model, enabled, priority)`，同一 Provider 下模型 ID 唯一；启停和优先级按模型行配置（一处配置一处修改）。
3. **调度候选 = Provider × 启用模型**：翻译排序先 Provider 优先级再模型优先级；任务 payload 快照 `provider_id + model_id + model 字符串`，幂等键随快照变更（相同版本 + 相同模型仍幂等）。已排队任务按快照的模型 ID 读取，配置修改不影响排队任务。
4. **Key 仍在 Provider 级**：同一服务的模型共用 Key 池；冷却与审计按密钥行记录（`llm_calls.model` 记实际请求模型字符串；密钥标识后来改记掩码，见 [API Key 直接录入](2026-10-08-API-Key-直接录入.md)）。
5. **迁移 0006**：新建表后，把每个既有 Provider 的 `model` 单值迁成一条启用模型行（沿用该行原 `updated_at` 作时间戳），再删除 `llm_providers.model` 列；`llm_providers.priority` 列保留但不再读写。历史译文、任务和审计记录保持原字符串不动。

## 影响范围

- 领域：`Provider` 移除 `model`，`ProviderModel` 新增。
- API：`ProviderResponse` 不再有 `model`；模型 CRUD 在 `/api/llm/providers/{id}/models`。
- 前端：模型配置页改为左（供应商列表）右（连接详情 / 模型列表 / Key 引用）布局，模型行内启停、编辑和优先级调整。
- 兼容性：升级后旧翻译任务按快照 model 字符串查不到新表行时，按 Provider 兜底。无 v2 生产数据；测试库走全新迁移。
