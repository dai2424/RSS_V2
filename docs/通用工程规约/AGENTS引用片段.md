```text
# 项目入口规则

开始任何代码、测试或文档任务前：

1. 读取 docs/项目说明/技术选型.md，确认“用什么”；
2. 读取 docs/项目说明/开发规范.md，确认“怎么写”；
3. 读取 docs/阶段目标/ 中当前阶段计划，确认“本次交付什么”；
4. 如果出现未覆盖的设计取舍，先记录 docs/决策记录/ 再实现。

通用规约位于 docs/通用工程规约/，至少遵守其中的开发规范、技术与架构、配置安全、测试质量和 Git 工作流。

## 强制边界

1. 领域代码不做 IO；应用层不依赖具体适配器；具体实现只在组合根装配。
2. 业务代码通过抽象接口访问存储、网络、文件和第三方服务。
3. 结构迁移使用递增且不可修改的迁移文件；业务代码不得隐藏结构变化。
4. 后台任务统一使用项目规定的持久化执行机制；处理函数必须幂等并支持重试和恢复。
5. 配置、密钥、日志、数据库、缓存和运行产物不得污染版本库。
6. 错误必须记录、分类并返回可诊断结果；禁止裸异常和静默吞错。
7. 每项改动使用独立临时分支和 worktree，完成检查后再同步基线、合并和清理。

## 完成定义

- 相关单元、契约、集成和必要的端到端检查通过；
- 全新环境可初始化，失败、重试、幂等和恢复行为有验证；
- 文档、注释、配置说明与实现一致；
- 提交不包含密钥、数据库、日志、缓存、构建产物或运行输出；
- 没有未说明的依赖方向、复杂度或安全问题。
```
