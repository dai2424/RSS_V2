# RSS v2 Web 界面规范

> 状态：v0.1 建议版（2026-10-07）
> 用途：统一页面布局、视觉、交互和界面验收；前端技术栈见[技术选型.md](技术选型.md)，代码边界见[开发规范.md](开发规范.md)。
> 标注：**[必须]** 每个相关页面都要满足；**[默认]** 第一版起点，可根据页面样稿调整并同步本文档。

## 1. 目标与适用范围

界面服务于“找到消息 → 阅读原文 → 查看证据版本 → 做出核验”。第一版覆盖消息列表、消息详情、证据和核验；导航只显示已经可用的功能，不提前堆入图谱、报表和未实现的页面。

当前 RSS 订阅竖切先实现来源、消息、翻译、任务与模型配置。证据和人工核验规则在对应后续竖切实施，不能因此在当前导航中放置未实现入口。

已确认的视觉方向为简洁、中性、桌面优先的工作台；品牌色、最终密度和布局细节以第一张页面样稿为准。本规范不替代页面设计，也不授权开始实现页面。

## 2. 视觉与设计变量

- [必须] 使用 shadcn/ui 和 Tailwind；颜色、圆角、阴影统一通过全局设计变量管理，不在各页面分别配置主题。
- [必须] 使用语义颜色：`background`、`foreground`、`primary`、`muted`、`border`、`ring`、`destructive` 等；补充 `success`、`warning` 时集中声明，同时定义对应文字颜色。
- [默认] 第一版以浅色主题验证，深色主题按需加入；以文字、分隔线和留白组织信息，不给每段内容套一层 Card。
- [默认] 间距使用 4px 基准：4 / 8 / 12 / 16 / 24 / 32；按钮和表单控件统一高度 36px，窄屏触摸操作区至少 44px。
- [默认] 使用系统中文字体；界面正文 14px，阅读正文 16px、行高约 1.75，页标题 24px；辅助文字不小于 12px。
- [必须] 相同操作使用相同图标和文案；纯图标按钮提供可访问名称，必要时补充 Tooltip。

shadcn/ui 的语义变量和前景/背景配对方式参考[官方主题文档](https://ui.shadcn.com/docs/theming)。

## 3. 页面布局与窄屏

- [默认] 桌面使用统一应用外壳：侧栏、页标题区、筛选/操作区和内容区；侧栏约 240px，内容内边距 24px。
- [必须] 每页有一个明确主标题；高强调主操作集中在同一位置，次要操作使用 outline、ghost 或菜单。
- [必须] 消息详情、证据详情有可直接打开的 URL；从列表进入再返回，保留筛选、分页和滚动位置。
- [默认] 宽度小于 1024px 时侧栏改为可关闭的 Sheet；小于 768px 时多栏内容纵向排列，筛选和按钮允许换行。
- [必须] 窄屏仍能完成阅读、查看证据和核验；页面整体不得横向溢出，数据表格可在自己的容器内横向滚动。
- [必须] 长标题、链接、中文、emoji 和长英文串可换行；省略显示必须提供查看完整内容的入口。

## 4. 列表、阅读与证据

| 场景 | 必须展示的内容 | 交互要求 |
| --- | --- | --- |
| 消息列表 | 标题、来源、发布时间、证据状态 | 标题是可聚焦链接；筛选可清空，分页范围明确 |
| 消息详情 | 标题、原文链接、来源、发布时间、采集时间、版本历史 | 正文可选择和复制；历史版本可查看 |
| 证据详情 | 引用文本、确切消息版本、原文上下文、校验结果 | 高亮引用在该版本中的位置，不能用最新正文替代历史引用 |
| 核验 | 待判断内容、关联证据、已有核验记录 | “接受”和“标记问题”含义明确，问题原因可填写，提交后可查看历史 |

- [必须] 执行状态和人工核验状态分别展示；“执行完成”不能显示成“已核验”。
- [必须] 状态同时有文字，颜色只辅助表达；无证据、引用失效或旧版本引用必须如实提示。
- [必须] 时间按统一显示时区展示，第一版默认 Asia/Shanghai，并标明时区；缺失发布时间显示“未知”，不以采集时间冒充。
- [默认] 阅读正文限制在约 48rem 宽度；列表可以更宽，便于比较字段。

## 5. 加载、空态与错误

| 状态 | 界面行为 |
| --- | --- |
| 首次加载 | 内容区 Skeleton 或加载提示，保留导航和页面结构 |
| 刷新中 | 保留已有数据并显示刷新提示，避免整页闪烁 |
| 尚无数据 | 说明为什么为空，并提供当前可用的下一步操作 |
| 筛选无结果 | 显示“没有匹配结果”，提供清空筛选 |
| 读取失败 | 显示可理解的原因和重试入口，不能伪装成“暂无数据” |
| 提交失败 | 保留输入和当前位置，允许修正或重试 |
| 权限不足或会话过期 | 提示登录/重新登录，保留可恢复的操作上下文；不在持久存储中保存敏感输入 |

[必须] 不使用假统计、固定“正常”状态或演示数据冒充真实结果。开发预览的样例必须标为“示例数据”。提示不得暴露 API 密钥、数据库路径或异常堆栈。

## 6. 表单与操作反馈

- [必须] 每个输入有 label，必填、格式和错误在对应字段附近说明；placeholder 不能代替 label。
- [必须] 提交期间按钮有进度反馈并防止重复提交；收到服务端成功响应后才能显示“已保存”。
- [必须] 核验、版本和任务结果以服务端为准；失败时不保留虚假的成功状态。
- [必须] 不可逆操作说明对象和影响后再确认；普通导航、查询和刷新不弹确认。
- [必须] 表单有未保存修改时，关闭或离开前允许继续编辑或放弃；提交失败不得清空表单。
- [默认] Dialog 用于短表单或确认；Sheet 用于临时查看；长正文和多步骤核验使用独立页面，避免多层弹窗。
- [必须] 关键错误留在页面或字段内，Toast 只做辅助反馈；异步任务的“已排队”和“已完成”使用不同文案。

## 7. 键盘、可访问性与内容安全

- [必须] 导航、筛选、详情和核验可通过键盘完成；保留清晰的 focus 样式，不用仅支持鼠标的整行点击替代链接。
- [必须] 模态 Dialog/Sheet 打开后管理焦点、限制焦点到弹层内，支持 Esc 关闭；关闭后恢复到触发控件，未保存修改按上一节处理。
- [必须] 普通文本对比度至少 4.5:1，大字号文本至少 3:1；必要控件轮廓和焦点指示至少 3:1。此处是验收基线，不代表已取得完整 WCAG 合规认证。
- [必须] 语义结构正确，表格有表头，页面有主内容区；动态错误/成功提示可被辅助技术识别。
- [必须] RSS HTML 和 Markdown 按不可信内容处理；禁止直接注入未清洗 HTML，链接协议须校验，不允许执行脚本。
- [必须] 动画服从系统减少动态效果设置，不影响阅读和输入。

依据：[W3C WCAG 2.2](https://www.w3.org/WAI/WCAG22/quickref/)、[W3C 模态对话框交互](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。

## 8. 组件复用与界面红线

- [必须] 通用 Button、Input、Dialog、Sheet 等集中在 `components/ui/`；页面布局、空态和错误态集中复用，业务组件进入对应 `features/`。
- [必须] 不复制一套组件来给单个页面换皮；新增变体在原组件中扩展，保持键盘行为和语义。
- [必须] 相同业务状态使用同一套映射，不允许各页自行解释状态码。
- [必须] 不创建不能工作的按钮、假的健康标记或无法打开的菜单；暂未实现的功能从页面范围中移除。
- [必须] 更换全局主题、导航或页面骨架时同步本规范；第一张样稿确定后，其设计变量作为后续页面基线。

## 9. 页面完成标准

- [ ] 在 1440px 桌面、768px 窄屏和 390px 手机宽度实际检查布局，无遮挡或页面横向溢出。
- [ ] 使用长标题、长正文、缺失时间和多个历史版本样例检查阅读与引用跳转。
- [ ] 加载、空态、无匹配、错误、提交中和提交失败均可复现。
- [ ] 从消息列表打开详情、检查证据、完成核验再返回，筛选和位置可恢复。
- [ ] 仅使用键盘完成主流程，弹窗焦点、标签和对比度经过检查。
- [ ] 核验及版本相关交互有行为测试；视觉检查保留代表性截图，不以 build 成功代替界面验收。
