# 通用工程规约

这是一套可复制到其他项目的业务无关工程规约。它约束工程治理、模块边界、数据演进、后台任务、配置安全、测试和 Git 交付流程，不预设语言、框架、数据库、云服务或部署平台。

## 使用方式

1. 复制整个 `通用工程规约` 目录到目标项目的 `docs/` 下。
2. 在目标项目入口文档中引用 `AGENTS引用片段.md`，或把其中的规则合并进现有 `AGENTS.md`。
3. 搜索并填写所有 `<...>` 占位符。
4. 根据项目实际情况启用或删除标记为 `[可选]` 的章节。
5. 把技术栈、运行命令、目录名称和部署方式写入目标项目自己的技术附录，不要把本模板改成另一套业务规范。

## 规则等级

- **[必须]**：所有适用场景都必须满足。
- **[CI]**：应由自动化检查持续验证。
- **[评审]**：合并前由维护者检查。
- **[约定]**：默认做法，偏离时在提交说明或决策记录中解释。
- **[可选]**：只有项目采用对应能力时启用。

一条规则可以同时带多个等级，例如 `[必须][CI]`。

## 需要项目自行决定的内容

- `<项目名称>`、`<基线分支>`、`<运行目录>` 和 `<团队名称>`。
- 语言、框架、存储、消息系统、部署平台及其版本。
- 分支命名、提交信息语言和发布流程。
- 复杂度阈值、性能目标、数据保留周期和备份策略。
- 是否启用持久化任务、界面、端到端测试或多环境部署。

模板的目标是提供可审查的默认边界。项目如果需要偏离，应记录原因、影响和重新评估条件。
