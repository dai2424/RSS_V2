# Git 工作流

本文件用于让每项改动可隔离、可审阅、可回滚。项目可以调整分支前缀和提交语言，但必须保留隔离、检查和可恢复原则。

## 1. 强制规则

- [必须] 每项代码、测试或文档改动都在独立临时分支和独立 worktree 中完成。
- [必须] 开始任务时记录基线分支 `<基线分支>` 和工作树状态；已有未提交改动不得重置、覆盖或自动混入新任务。
- [约定] 临时分支使用 `<分支前缀>/<简短任务名>`，例如 `codex/<task>`。
- [必须] 一个完整功能、竖切或修复对应一个完整提交；禁止提交半成品。
- [评审] 合并前将最新基线同步到临时分支，在临时分支解决冲突并重新执行适用检查。
- [评审] 检查通过后只使用 fast-forward 合并回基线。
- [评审] 合并成功后删除已合并分支并归档或移除 worktree。
- [必须] 未合并、检查未通过或仍有冲突时，不得清理分支和 worktree。

## 2. 单项改动流程

```text
检查工作树与当前分支
        ↓
确定基线分支
        ↓
创建临时分支和独立 worktree
        ↓
实现、测试、提交
        ↓
同步最新基线并处理冲突
        ↓
再次执行适用检查
        ↓
fast-forward 合并
        ↓
删除分支并归档 worktree
        ↓
确认基线工作树状态
```

## 3. 冲突和异常

- [必须] 禁止使用强制重置、强制 checkout、强制推送或删除文件绕过冲突。
- [约定] 机械冲突可以在临时分支处理；涉及产品行为、数据兼容或安全取舍的冲突必须保留现场并请求决策。
- [必须] 终端中断后先用 worktree 和分支列表找回现场，再继续或明确恢复。
- [评审] 合并失败时保留临时分支，修复后重新同步、检查和合并。
- [约定] 并行任务一任务一分支一 worktree，不共享可写 checkout。

## 4. 提交信息

- [约定] 使用 `<类型>: <描述>`，类型可从 `feat`、`fix`、`refactor`、`docs`、`test`、`chore` 中选择。
- [必须] 描述说明最终行为或目的，不写“临时”“调试中”等未完成状态。
- [评审] 提交只包含当前任务相关的代码、测试和文档。

## 5. 提交前检查

- [ ] 工作树没有不明来源的改动。
- [ ] 所有适用检查通过。
- [ ] 新增文件、迁移、配置示例和文档已包含。
- [ ] 没有数据库、日志、缓存、密钥、构建产物或运行输出。
- [ ] 提交信息符合项目约定。
