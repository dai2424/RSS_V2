# 决策记录：API Key 直接录入并保存在运行目录数据库

> 状态：已实施（2026-10-08）
> 背景：原设计只在界面保存 Key 引用名，真实密钥必须预先放在环境变量 `RSS_LLM_KEY_<引用名>` 中。用户确认改为直接在模型配置页填写 API Key。

## 结论

1. **录入方式**：模型配置页的“API Key”直接填写密钥值；同一 Provider 可保存多枚 Key（各自优先级与启停），保留失败切换与冷却调度。
2. **存储位置**：密钥值只保存在运行目录数据库（`runtime/db`，已 gitignore 的 `llm_provider_keys.secret`），不进入代码仓库、`env/`、日志、审计表和 API 响应。
3. **回显规则**：界面与接口只返回末四位掩码（`••••••••abcd`）；录入与替换弹层提供显示/隐藏切换核对明文，保存后不再提供明文回看。
4. **审计**：`llm_calls` 与 `translations` 的列名由 `key_ref` 改为 `key_masked`，只记录掩码标签；历史数据保留原引用名字符串。
5. **迁移 0007**：重建 `llm_provider_keys`（`secret` 列）并重命名审计列。旧引用行只保存环境变量名、没有可兑换的密钥值，因此不迁移数据；升级后需在界面重新填写 API Key（当前无生产数据）。
6. **代码简化**：移除 `EnvironmentSecretResolver` 与注入到翻译用例的 `secret_available` 回调；可用密钥判断改为“启用且未冷却且密钥值非空”。

## 影响与边界

- 本机免认证阶段，能访问本机 API 的人即可读取或替换密钥；局域网部署前必须补齐认证（沿用技术选型 §10 的既有约束），并重新评估数据库文件权限与备份的密钥保护。
- 备份含密钥（`VACUUM INTO` 产物），备份文件的存放与分发视同密钥管理；文档与运维说明不得把备份提交到仓库。
- 前端不再提示配置环境变量；`start.cmd` 与 worker 不再要求密钥环境变量（仅保留运行目录等基础配置）。
