# RSS v2 项目结构

本文档描述第一版最小闭环的目录边界。代码目录只保存源代码、迁移、测试和文档；数据库、密钥、日志和运行产物写入配置指定的运行目录。

```text
RSS_v2/
├── AGENTS.md
├── pyproject.toml
├── uv.lock
├── start.cmd                    # Windows 一键启动入口，可双击或在终端执行
├── frontend/
│   ├── src/
│   │   ├── App.tsx              # 路由与懒加载装配
│   │   ├── components/          # 通用布局、状态组件；ui/ 保存 shadcn/ui 基础组件
│   │   ├── features/            # sources/messages/tasks/providers：页面、数据 hooks 和展示组件
│   │   ├── lib/                 # 时间、状态映射、链接校验等通用工具
│   │   └── api/generated.ts     # OpenAPI 生成类型，不手工编辑
│   └── package.json
├── migrations/
│   └── NNNN_description.sql     # 编号递增、已执行后不修改
├── config/                      # 无敏感信息的结构化配置
├── env/                         # 开发密钥，必须被 gitignore
├── runtime/                     # 数据库、备份、构建产物；不进入 Git
├── scripts/                     # 检查、导入和开发辅助脚本
├── tests/
│   ├── fixtures/                # 固定 RSS、LLM 和 API 样例
│   ├── contract/                # 端口和仓储契约测试
│   ├── integration/             # API、迁移和 worker 集成测试
│   └── unit/                    # 领域与用例测试
├── docs/
│   ├── 项目说明/                # 技术选型、开发规范、Web界面规范和项目结构
│   └── 阶段目标/
└── src/rss_v2/
    ├── domain/                  # 纯领域对象和领域异常
    ├── ports/                   # Protocol 接口；复用 llm 协议
    ├── services/                # 用例和业务规则，只依赖 domain/ports
    ├── adapters/                # SQLite、RSS、文件等具体实现；sqlite/v1_* 负责旧库只读导入
    ├── api/                     # FastAPI APIRouter 和异常处理
    ├── llm/                     # LLMProvider 协议；实现在 adapters/llm
    ├── tasks/                   # 任务定义、领取、worker 入口
    ├── settings.py              # 配置读取与校验
    ├── bootstrap.py             # 唯一的生产依赖组合根
    ├── launcher.py              # 准备前端并管理 API、worker 两个独立子进程
    └── main.py                  # API 和 CLI 启动入口
```

## 依赖规则

```text
api ──▶ services ──▶ ports ◀── adapters
                       ▲           │
                     domain ◀──────┘
```

- `domain/` 不导入项目内其它包，也不做网络、文件或数据库 IO。
- `ports/` 只声明领域接口，不出现连接、游标、SQL 或数据库行对象。
- `services/` 不知道 SQLite、HTTP 客户端或模型供应商。
- `adapters/` 实现端口；业务 SQL 只出现在 SQLite 适配器，schema SQL 只出现在 `migrations/`。
- `api/`、`tasks/` 和 CLI 不直接实例化适配器，统一调用 `bootstrap.py`。
- 测试可以在测试组合根中选择 SQLite、内存仓储和 fake provider。

## 运行目录

默认运行目录由配置决定，至少包含：

```text
<runtime>/
├── db/          # SQLite 数据库和备份
├── logs/        # API、worker、采集和 LLM 日志
├── frontend/    # Vite 构建产物（可通过 RSS_FRONTEND_DIST 修改）
└── outputs/     # 可选导出文件和临时产物
```

这些目录不进入 Git。后端测试使用系统临时目录；浏览器验收使用隔离的 `runtime/e2e/`，截图写入 `frontend/test-results/`。不能写入业务数据库或固定的 demo 目录。
